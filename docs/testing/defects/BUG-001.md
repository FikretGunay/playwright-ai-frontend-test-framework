# BUG-001

- **ID:** BUG-001
- **Title:** [Registration form / Age validation] Ages below 18 (15 and 17 observed) are accepted
- **Requirement reference:** REQ-004, US-004, AC-011 (Age must be a number from 18 to 65, inclusive)
- **Linked test cases:** TC-011 (Fail), TC-016 (Fail); TC-018 is also affected because its setup uses Age 17
- **Bug description:** The form does not show the error `Age must be between 18 and 65.` when Age is below 18. Age 17 and Age 15 produce no Age error, although the requirement allows only 18 to 65. Age 0 and negative values are still rejected (TC-020, TC-015 passed). Age 16 was not executed.
- **System part:** Client-side validation in `index.html`, the Age lower-bound check in the `validate()` function. Cause suspected from code review: the lower-bound comparison uses 15 instead of 18. Not yet confirmed by a fix and rerun.
- **Severity:** Major
- **Priority:** High
- **Tester:** QA (test engineer)
- **Frequency:** Always. Reproduced for both values tried (15 and 17) in the only automated run so far (2026-10-22); the validation condition is deterministic. Not yet reproduced manually.
- **Consequence:** Users below the minimum age can complete the registration. The business rule of the form is not enforced and ineligible users receive a `Registration successful` message.
- **Environment:** Chromium (Playwright headless shell 156.0.8078.4), Windows 11 Pro, `index.html` opened from the file system, no app version or commit available, default viewport.
- **Steps to reproduce:**
  1. Open `index.html`.
  2. Enter Name `Anna Svensson`, Email `anna@example.com`, Password `password123`.
  3. Enter Age `17` (or `15`).
  4. Click Submit.
- **Expected result:** `error-age` shows `Age must be between 18 and 65.`
- **Actual result:** `error-age` is not displayed (element not found after a 5 s timeout).
- **Evidence:**
  - `test-results/registration-Age-age-17-is-rejected-boundary-min---1-/test-failed-1.png`
  - `test-results/registration-Age-age-15-is-rejected-below-minimum-/test-failed-1.png`
